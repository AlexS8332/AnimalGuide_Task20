# Заметки по ходу — AnimalGuide v19: конвейер MCP-инструментов

Черновик: план, решения по ходу, замеры. Заметки v18 — в истории git
(`git show v18:notes.md` в репозитории v18).

## Условие

Несколько MCP-инструментов (search, summarize, saveToFile) и конвейер:
первый получает данные, второй обрабатывает, третий сохраняет. Проверить
автоматическое выполнение цепочки и корректность передачи данных между
инструментами. Итог — автоматический конвейер из нескольких MCP-инструментов.

## Что уже было в v18 и чего не хватало

В v18 выпуск фактов собирался внутри демона одним вызовом `run_now issue`:
досье → редактор → проверяющий → SQLite. Шаги были, но это не MCP-инструменты,
а функции одного процесса; цепочку никто снаружи не вёл и передачу данных
между шагами не проверял.

Добавляется только недостающее:

1. Три самостоятельных MCP-инструмента демона:
   - `search` — получить данные: запрос (mdd-id, латынь, английское или
     русское название) → вид MDD → досье (MDD, Википедия, GBIF). Без модели.
   - `summarize` — обработать: досье → 3–5 фактов (редактор + проверяющий
     v18, `trivia.Builder.Compose`). Платно, под дневным лимитом.
   - `save_to_file` — сохранить: факты → Markdown или JSON в
     `<data>/exports/`, с перечитыванием и сверкой sha256.
2. Конверт данных между шагами: kind, data, digest (sha256 канонического
   JSON), input (digest входа). Вход — конверт целиком (`input`) или только
   ссылка (`ref` = digest, демон держит выходы шагов в SQLite).
3. Исполнители цепочки на стороне клиента, по MCP:
   - код (`pipeline.Run`) — три вызова подряд, проверки на каждом шаге;
   - модель (`pipeline.RunAgent`) — модель сама зовёт три инструмента,
     код потом проверяет её цепочку.
4. CLI `cmd/pipeline` и вкладка «Конвейер» в окне «Интересные факты».

Проверки передачи: сервер пересчитывает отпечаток входа (порча → ошибка),
клиент пересчитывает отпечаток ответа и сверяет «вход шага N+1 = выход
шага N», файл несёт отпечатки всей цепочки.
